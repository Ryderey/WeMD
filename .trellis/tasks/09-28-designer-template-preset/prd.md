# PRD：可视化设计器套用模板再微调

权威方案：`docs/plans/2026-09-28-designer-template-preset.md`（用户已审核，其中「审核与交接修订」一节为准）。
分支：`feat/designer-template-preset`（自 `feat/reading-edition-theme` HEAD `7c50096` 建立）。

## 需求

1. 主题管理左侧「自定义主题」区域常驻五个模板入口（青岚/素笺/墨刊/蓝图/朱砂），带文字标识；模板不可删除、不可改名、不可直接保存修改。
2. 模板必须先复制：点「复制并微调」立即创建普通自定义主题副本（名称 `模板名 (副本)`），选中该副本并进入可视化编辑；副本立即持久化，但不自动应用到文章。
3. 副本进入现有「可视化设计」控件，支持微调、保存、再次编辑、应用；其余 12 款内置主题保持现有行为不变。
4. **保真门槛**：零修改的复制在预览、保存、刷新后必须与源模板观感一致，不得悄悄退回通用设计器版式。未通过保真验收不得登记为可微调模板。
5. 模板身份判定复用现有字段：`isBuiltIn && editorMode === "visual" && designerVariables != null`；不新增 `isPreset`/`canDelete`，不建第二套主题存储。
6. 模板只出现在列表的一处：当前面板的「内置主题」分组过滤掉这五款，全局 `builtInThemes` 仍含它们，其他主题选择器照常列出。
7. 选中模板只切换面板预览，不改变文章主题；显示只读名称与提示「模板不可修改，复制后可进行可视化微调」，操作按钮为「复制并微调」与「应用主题」。
8. 新增表达能力的字段全部可选，缺省时旧主题生成规则逐字不变；兼容回退在生成器读取处完成，不依赖面板 normalize。
9. 运行时输入（JSON / localStorage）必须校验：数字有限值与范围、枚举白名单、宽度限定单位、颜色/字体合法值或回退；不得把任意字符串插入新增 CSS 声明。
10. 副本 JSON 自包含，脱离内置模板注册仍能重建；模板后续改版不回流副本。

## 范围外

章节标签（另开分支用「作者显式标注」实现）、运行时 CSS 解析、脏字段追踪、模板市场、云端同步、模板升级合并、顺手改 `reading-editions.ts` 的样式。

## 验收标准

### 列表与权限

- [ ] 无用户自定义主题时仍显示五模板与「我的主题」空态。
- [ ] 当前面板内五款不重复出现（内置分组已过滤）。
- [ ] 模板不能删除 / 改名 / 保存修改。
- [ ] store 的更新与删除对模板 ID 无效果。

### 复制流程

- [ ] 一次点击即选中 visual 副本并进入可视化编辑。
- [ ] 刷新后副本仍存在；副本不自动应用到文章。
- [ ] 源模板与两个副本的嵌套变量互不影响（深拷贝）。

### 控件与状态

- [ ] 零修改打开不出现伪脏状态（「保存修改」不可用）。
- [ ] 修改生效，保存后脏状态清除。
- [ ] 连续切换两个副本无上一份 CSS / 变量闪回或覆盖。

### 保真

- [ ] 统一样例经实际解析后的 DOM 覆盖检查通过，脚注、非 hljs 代码、链接图注等节点存在；图片加载成功。
- [ ] 小图全宽、普通/滑动图片间距、超长代码溢出及多行脚注布局在两档视口对照通过。
- [ ] 五款在「原模板 / 零修改副本 / 保存重开 / 刷新」四种状态下的统一样例计算样式与截图对照通过。
- [ ] 所有发现的差异有明确处理结论（补齐或经审核批准）。

### 兼容与输入

- [ ] 修改生成器前冻结旧配置/旧 CSS 基线；缺省输出与旧基线逐字比较，不用修改后的两个路径互相比代替。
- [ ] 老 visual 主题、老 CSS 主题、其余 12 款内置主题输出不变。
- [ ] 旧 JSON 缺新字段可导入并回退；新 JSON 往返不丢新字段。
- [ ] 无效新增字段不产生无效 CSS、不崩溃。

### 导出与应用

- [ ] JSON 导入后仍可编辑；CSS 导出对应保存结果。
- [ ] 应用与历史快照正确，预览与正文输出一致。

### 微信与桌面

- [ ] 复制内联样式保留短线、代码边框、字体与页面间距。
- [ ] 微信粘贴、保存、重开人工验证（无法执行时明确标注）。
