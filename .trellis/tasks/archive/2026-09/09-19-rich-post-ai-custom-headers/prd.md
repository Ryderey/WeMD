# PRD：导出图文 AI 自定义请求头与会话 ID

来源方案：`.agentdocs/rich-post-ai-custom-headers-plan.md`（本地保存，不入版本控制）。

## 背景

OpenCode Go 端点要求非空 `x-opencode-session` 请求头，缺失时返回 HTTP 400。现有“导出图文”AI 配置只发送固定的 Authorization 与 Content-Type，无法接入此类端点。官方文档要求同一会话使用稳定的会话 ID（用于路由与提示词缓存），不能实现为每个请求都变化的随机值。

## 需求

1. AI 配置支持通用自定义请求头：键值行编辑，支持新增、删除、启用/停用、本地记住。
2. 值类型支持“固定文本”与“自动会话 ID”两种；自动模式由运行时生成稳定 UUID。
3. 自定义请求头在 Web/Electron 两端、探测与改写两条路径均生效。
4. 同一次导出图文会话内，探测与多次改写共用同一个会话 ID；关闭重开、切换文章、变更 AI 端点后更换。
5. 只持久化勾选“本地记住”的行；自动模式只保存配置不保存生成的 ID；取消记住即从持久化移除。
6. 发送前严格校验：大小写不敏感的重复名、非法字段名/值、保留头（Authorization、Content-Type、Host、Content-Length、Cookie 等）、超量（≤20 行、合计 ≤16KB）一律拒绝，且错误不泄露 Key 或头值。
7. Electron 主进程重新校验 IPC 输入，不依赖渲染进程校验；沿用现有 API Key 端点绑定检查。
8. 旧配置（无 customHeaders）加载后行为与现状完全一致。

## 范围外

供应商适配框架、任意请求体配置、变量表达式、多供应商配置档案、重试策略、流式请求、Nest 服务端与秘密存储格式变更。

## 验收标准

- [ ] 无自定义头时，旧配置加载、探测、改写与 API Key 处理保持原行为（回归测试通过）。
- [ ] Web 与 Electron 的探测及改写都携带启用的自定义头；停用或删除后不再发送。
- [ ] 大小写重复、非法名称/值、保留头、超量配置在发送前被拒绝；绕过界面直接调 IPC 同样被拒绝。
- [ ] 同一会话内多次请求（探测+改写+重新生成）ID 一致；关闭重开、切换文章或端点后 ID 改变；正文编辑不改变 ID。
- [ ] 只有勾选记住的行进入 localStorage；取消记住可清除；自动 ID 与 API Key 不进入普通配置存储。
- [ ] 错误提示不泄露 Key 或头值；字段校验错误不误报为 CORS/网络错误。
- [ ] 请求测试断言实际 fetch 参数（含 headers）；Electron 覆盖 IPC 解析后自定义头字段不会丢失。
- [ ] 真实联调：比较缺少/携带 `x-opencode-session` 的结果，并完成一次真实改写（正文与高亮词解析）。
- [ ] 联调只发送专用最小样例；凭据不写入代码、文档、测试或版本控制。
