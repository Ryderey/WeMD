# PRD：引用块超长时上下滑动（长提示词场景）

## 背景

作者常把很长的提示词/说明放进引用块，公众号里读起来占屏过半。参考文章存在成熟的
「固定高度 + 内部上下滑动 + ▲上下滑动查看全文」效果，且发布链路验证微信不剥这些内联样式（见 research/）。

## 需求

1. 主题设计器「引用」区新增开关：**超长时上下滑动**，附**滑动高度**设置。
   - 默认高度 240px（与参考文章同款），可调范围 160–800px。
   - 开关关闭（或老主题缺该字段）时行为与现状完全一致。
2. 复制到公众号（`copyToWechat`）：引用块容器内联样式附加 `max-height: <滑动高度>px; overflow-y: auto; overflow-x: hidden; -webkit-overflow-scrolling: touch;`。
3. 复制时，凡引用正文 ≥ 200 字且滑动已开启，在该引用块**之后**插入居中 12px 提示行「▲上下滑动查看全文」。
   - 判定在真实浏览器里优先用实测溢出（scrollHeight > clientHeight，760px 宽下测得溢出 ⟹ 更窄的手机必溢出）；无真实布局（jsdom）时回退字数阈值。
4. 预览（主题 CSS 生效处）引用块同样可滚，但**不**出现提示行（提示行是复制时注入，照「链接转脚注」先例）。
5. 导出图片语境剥离滑动样式：引用全文完整进入长图，不静默折叠。
6. 「复制为 HTML」「导出 HTML」语境不做特殊处理（携带主题 CSS，滑动在支持 overflow 的环境自然成立）。

## 边界（不改）

- 不动 parser、不动 Markdown 语法、不做单个引用块的显式标注。
- 不改既有 6 个引用样式预设的视觉输出；滑动是独立开关，可与任一预设组合。
- 微信手机端读文为唯一目标语境：不承诺管理后台 iFrame 内滑动流畅度（那是编辑器视图）。

## 验收标准

- [ ] 60 份 designer 基线逐字节不变（新字段关闭时现有主题输出零字节变化）。
- [ ] 复制集成测试（wechatCopyCssIntegration 层级）：开启 + 长引用 → 序列化 HTML 中 blockquote 内联含 `max-height:240px;overflow-y:auto;overflow-x:hidden;-webkit-overflow-scrolling:touch;` 字面值（无 var()），且引用后有提示行；关闭 → 两者都不出现；开启 + 短引用 → 在真实浏览器语境不出提示行（jsdom 回退阈值行为单测覆盖）。
- [ ] 导出图片链路：blockquote 内联被剥离上述四项。
- [ ] 老 JSON 主题导入：缺字段 = 关闭，样式字节不变。
- [ ] 真机验证（用户执行）：桌面端复制 → 公众号后台粘贴 → 保存 → 手机预览：长引用内部可滑、提示行在位、短引用无变化。
